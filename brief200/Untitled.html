## ✅ Step 1 — Create the event_checkins table


Goal: Add a new table that stores one row per person per event, so we have a permanent attendance record separate from RSVPs. This must not affect any existing table.


What Cursor must do:


- Create a new migration file in supabase/migrations/ named with today's date and a clear suffix like _event_checkins.sql.


- The table must be called event_checkins and include columns for:

  - Unique id (uuid, primary key)

  - event_id (foreign key to events, cascade on delete)

  - campus_id (foreign key to campuses, set null on delete)

  - profile_id (foreign key to profiles, set null on delete)

  - member_id (foreign key to members, set null on delete)

  - rsvp_id (foreign key to event_rsvps, set null on delete)

  - is_dependant (boolean, default false)

  - dependant_name (text, nullable)

  - guardian_member_id (foreign key to members, set null on delete)

  - room (text, nullable)

  - seat (text, nullable)

  - security_code (text, nullable)

  - method (text, default 'self', with a check constraint allowing only: self, kiosk, scanner, staff)

  - checked_in_by (foreign key to profiles, set null on delete)

  - checked_in_at (timestamptz, default now)

  - synced_at (timestamptz, nullable)


- Add a unique constraint on (event_id, member_id) to prevent double check-in for members.


- Add indexes on event_id, member_id, and guardian_member_id.


- Enable row-level security.


- Add a policy allowing members to read their own check-ins (where profile_id matches the authenticated user, or guardian_member_id belongs to the authenticated user).


- Add a policy allowing staff roles to read all check-ins.


- Do NOT add insert/update/delete policies — writes go through the service role via API routes only.


- Do NOT modify event_rsvps or its ticket_scanned_at column — they stay for backwards compatibility.


Deliverable: Show the user the migration file path and full contents. Ask them to run it in Supabase before proceeding.

## ✅ Step 3 — Create the API routes


Goal: Four new API route files that read and write check-ins. They use the service role Supabase client, not the user session.


What Cursor must do:


Route 1: src/app/api/events/checkins/route.ts — POST handler

- Accepts JSON: eventId, optional profileId, memberId, rsvpId, dependants (array of { name, room? }), room, seat, method.

- Validates eventId is present.

- Looks up the event to get its campus_id. Returns 404 if event doesn't exist.

- Generates a 4-digit security_code (string, e.g., "4821").

- Upserts the primary check-in into event_checkins with the campus, profile, member, rsvp, room, seat, security code, and method. Uses onConflict: 'event_id,member_id' so re-checking in is idempotent.

- If dependants were provided, inserts one row per dependant: is_dependant: true, dependant_name, guardian_member_id: memberId, the same room, the same security_code, and the same method.

- Returns { primary, dependants } where each is the row(s) as inserted.


Route 2: src/app/api/events/[id]/checkins/route.ts — GET handler

- Fetches all check-ins for the given event, ordered by checked_in_at ascending.

- Returns camelCase mapped objects: id, eventId, campusId, profileId, memberId, rsvpId, isDependant, dependantName, guardianMemberId, room, seat, securityCode, method, checkedInAt.


Route 3: src/app/api/events/checkins/me/route.ts — GET handler

- Reads query params eventId and profileId.

- Returns the single check-in row where event_id matches and profile_id matches, or null if none.

- Returns camelCase fields: id, eventId, room, seat, securityCode, checkedInAt.


Route 4: src/app/api/events/checkins/today/route.ts — GET handler

- Reads query params campusId and profileId.

- Finds the single event today (from midnight to midnight, based on starts_at) matching the campus, ordered by starts_at ascending, limit 1.

- If no event or no profileId, returns { event: null, checkin: null, dependants: [] }.

- Otherwise fetches check-ins for that event where profile_id = profileId OR guardian_member_id = profileId.

- Splits into primary (non-dependant) and dependants array.

- Returns { event, checkin, dependants }.


Conventions:

- Use getSupabaseAdmin() from @/lib/supabase/admin.

- Return 503 if the DB isn't configured, 400 for missing required params, 500 for DB errors — matching the pattern in src/app/api/events/tickets/verify/route.ts.


Do NOT modify src/app/api/events/tickets/verify/route.ts.


Deliverable: Show the four new file paths and their contents.
